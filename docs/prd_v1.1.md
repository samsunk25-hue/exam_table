# 스마트 시험 감독 매니저 (Smart Invigilation Manager)
**버전:** 1.1 (MVP 및 고도화 기획안 - 엑셀 업로드 기능 추가)  
**작성일:** 2026-09-30
**목적:** 복잡한 제약조건을 최적화 알고리즘으로 해결하는 학교 맞춤형 클라우드 시험 감독 배정 노코드 앱.

---

## 1. 성공 기준 (Success Criteria)
이 앱의 성공 여부는 다음 지표로 평가합니다.
* **하드 조건 위반 배정:** 0건 (결함률 0%)
* **자동 배정 성공률:** 95% 이상 (잔여 슬롯 5% 미만)
* **수동 수정 필요 슬롯:** 전체 배정의 10% 이하
* **업무 형평성:** 교사별 누적 감독 점수(가중치 반영) 편차 최소화
* **시간 단축:** 개인별 시간표 및 전체 시간표 생성 시간 1분 이내
* **이력 추적:** 확정 이후의 모든 변경사항(100%) Audit Log 기록

방대한 기능을 안정적으로 구현하기 위해 버전을 분리합니다.

### MVP (최소 기능 제품) - 1차 개발 목표
- [x] 권한 분리 (관리자 / 일반 교사)
- [x] **기본 데이터 세팅 (표준 엑셀 양식 다운로드 지원 및 교사/기초시간표/시험일정/시험실 엑셀 파일 일괄 업로드)**
- [x] 교사별 불가시간 입력 (수동 및 직접 입력)
- [x] 1단계 하드 조건 + 2단계 소프트 조건 기반 **자동 감독 배정 엔진**
- [x] 미배정/충돌 원인 분석 및 관리자 수동 수정 UI
- [x] 전체 시간표 및 개인별 미니 시간표 출력 (웹 뷰어 및 PDF)

### V2 (고도화 및 자율 참여)
- [ ] 시수 형평성 대시보드 (가중치 기반 업무 점수화)
- [ ] 별도시험장(시간 연장, 일부 학생) 상세 로직
- [ ] 교사 간 감독 교환(Swap) 워크플로우 및 승인 시스템
- [ ] 출제 교사 '복도 대기' 등 예외 역할 세분화

### V3 (예측 및 외부 연동)
- [ ] 배정 시뮬레이션 (조건별 가중치 슬라이더 조절 및 결과 예측)
- [ ] 메신저(카카오톡 알림톡) 연동
- [ ] 과거 시험 데이터 기반 누적 분석 및 피로도 예측

## 3. UI/UX 화면 구조도

### [관리자 모드]
* **대시보드:** 현재 진행 중인 시험 프로젝트 현황 및 누적 통계
* **기본 설정:** 교사 관리 / 기초시간표 / 시험 일정 / 시험실 세팅 **(항목별 엑셀 양식 다운로드 버튼 및 엑셀 일괄 업로드/매핑 UI 제공)**
* **조건 수집:** 교사별 근무 불가 시간 현황 (승인/반려)
* **배정 시뮬레이션 & 자동배정:** 가중치 슬라이더 조절 및 결과(성공률, 미배정 사유) 미리보기
* **시간표 편집기:** 엑셀형 그리드 뷰 (드래그 앤 드롭, 충돌 경고)
* **승인 센터:** 교사 Swap 요청 관리
* **출력/알림 센터:** 전체/개인 시간표 PDF 인쇄 및 시스템 알림 발송

### [일반 교사 모드]
* **내 감독 시간표:** 본인에게 배정된 감독 일정 및 배정 사유 확인
* **불가 시간 관리:** 내 근무 불가 시간(출장, 연수 등) 제출 및 내역 확인
* **교환(Swap) 센터:** 동료에게 교환 요청 및 수신된 요청 수락/거절
* **공지/알림함:** 배정 확정 및 변경 알림(웹 푸시/이메일 기반)

## 4. 업무 워크플로우 (상태 변화 단계)

앱의 배정 프로세스는 단일 '확정'이 아닌 7단계로 관리됩니다.
1. **초안 생성:** 앱에서 제공하는 표준 엑셀 양식을 활용하여 시험 일정 및 기초 데이터(교사, 시험실 등) 일괄 업로드 및 세팅.
2. **자동 배정 완료:** 알고리즘 실행 및 결과 도출.
3. **관리자 검토:** 시뮬레이션 확인, 미배정 슬롯 수동 할당.
4. **교사 공개 (Draft 공개):** 1차 초안을 교사들에게 열람 허용.
5. **교환(Swap) 기간:** 교사 자율 교환 요청 및 관리자 승인.
6. **최종 확정:** 확정 버튼 클릭 (누적 시수 DB 반영).
7. **변경 잠금 & 이력 관리:** 이후 수정 발생 시 `Audit_Log`에 강제 기록.

## 5. 배정 알고리즘 명세서 (ALGORITHM.md)

단순 빈자리 채우기(Greedy) 방식이 아닌, **후보자 점수화 최적화(Scoring Optimization)** 방식으로 작동합니다.

### 5.1. 역할 및 가중치 설정
* **일반 정감독:** 1.0점 / **부감독:** 0.8점 / **자습감독:** 0.6점
* **별도시험장(시간 연장):** 1.5점 / **복도 대기(출제자):** 0.5점

### 5.2. 배정 엔진 프로세스 (4단계)
* **[1단계] 하드 조건 필터링 (배정 절대 불가 조건)**
  - [x] 동시간대 중복 배정
  - [x] `Teacher_Availability`에 등록된 근무 불가 시간
  - [x] 별도시험장 연장 감독 직후 다음 교시
* **[2단계] 후보군 생성 및 소프트 조건 점수화**
  - (+50점) 기초시간표 일치 (해당 시간 원래 수업 교사)
  - (+30점) 누적 업무부담 점수 최하위권
  - (+20점) 연속 배정 아님
  - (+10점) 해당 학년 담임 아님
  - (-30점) 직전 교시 감독 수행함
  - (-40점) 누적 업무부담 점수 상위권 10%
* **[3단계] 정렬 및 매칭**
  - 각 슬롯별로 후보자 점수를 내림차순 정렬하여 고득점자 우선 배정.
* **[4단계] 예외 상황(미배정) 처리 및 설명 생성**
  - 조건 만족 교사가 0명일 경우 빈 칸으로 두고 관리자에게 경고창 출력.
  - *예시: "2-5반 수학 미배정 1명 (원인: 가용 인력 0명 - 출장 3명, 타 시험 감독 2명)"*
  - 배정된 교사에게는 "+50(기초일치), +20(비연속)" 형태의 배정 근거(Reason) 텍스트 저장.

## 6. 데이터베이스 스키마 설계 (DATABASE.md)

확장성과 이력 관리를 위해 데이터베이스를 고도로 세분화합니다.

### 6.1. 기본 및 계정 관리
* **`Users` (사용자/권한)**
  - `userID`, `teacherID` (Teachers 테이블 연동), `role` (Admin/Teacher), `email`, `active`
* **`Sessions` (시험 프로젝트)**
  - `sessionID`, `학교명`, `학년도`, `학기`, `시험명`, `상태` (Draft/Open/Locked)

### 6.2. 교사 및 제약 조건 관리
* **`Teachers` (교사 기본)**
  - `teacherID`, `이름`, `담당교과`, `담임학년반`, `누적_업무점수`(가중치 계산용), `기본역할`(일반/복도대기/제외)
* **`Teacher_Availability` (세부 일정 관리)**
  - `availID`, `teacherID`, `date`, `period`, `available`(T/F), `reason`(연수/순회 등), `source`(teacher/admin)
* **`Constraints` (배정 예외 규칙)**
  - `constraintID`, `sessionID`, `teacherID`, `type`(담임배제/특정시험배제), `priority`

### 6.3. 시간표 및 공간 관리
* **`Base_Timetable` (기초 시간표)**
  - `baseID`, `teacherID`, `요일`, `교시`, `학년반`, `과목`
* **`Exam_Slots` (시험 시간 메타데이터)**
  - `slotID`, `sessionID`, `date`, `period`, `실제시작`, `기본종료`, `학년`, `과목`, `유형`(시험/자습)
* **`Exam_Groups` (별도시험장 및 그룹 분리용)**
  - `groupID`, `slotID`, `학년반`, `응시인원`, `roomType`(일반/연장/특수), `연장종료시간`
* **`Rooms` (물리적 공간)**
  - `roomID`, `실명`, `필요정감독수`, `필요부감독수`, `공간유형`(교실/별도실/복도)

### 6.4. 결과 및 이력 관리
* **`Assignments` (최종 배정 매핑)**
  - `assignID`, `sessionID`, `slotID`, `roomID`, `teacherID`, `역할`(정/부/연장/복도), `배정근거`(Scoring Text), `상태`(확정/교환대기)
* **`Swap_Requests` (교환 시스템)**
  - `requestID`, `sessionID`, `요청교사ID`, `대상교사ID`, `내_배정ID`, `바꿀_배정ID`, `사유`, `상태`(요청/수락/승인/반려)
* **`Notifications` (알림 현황)**
  - `notiID`, `teacherID`, `sessionID`, `type`(배정완료/교환요청/반려), `message`, `status`(Unread/Read), `sentAt`
* **`Audit_Logs` (행동 추적 - 매우 중요)**
  - `logID`, `sessionID`, `userID`(행위자), `action`(Create/Update/Delete/Swap), `targetType`(Assignment 등), `beforeValue`, `afterValue`, `createdAt`

## 7. UI/UX 디자인 가이드라인 (Design System)

**핵심 콘셉트:** 시각적 피로도를 낮추는 고대비(High-contrast) 기반의 직관적 클린(Clean) 디자인

### 7.1. 색상 팔레트 (Color Scheme)
전체적으로 밝고 화사한 톤을 유지하되, 상태(정상/경고)를 명확히 구분할 수 있는 파스텔톤을 활용합니다.
* **배경색 (Background):** 눈부신 순백색(#FFFFFF)보다는 피로감이 적은 아주 밝은 웜그레이(#F8F9FA) 또는 연한 아이보리 톤 사용.
* **메인 컬러 (Primary):** 신뢰감과 안정감을 주는 **스카이 블루(#4A90E2)** 또는 **민트 그린(#2ECC71)**. 주요 버튼과 강조 표시에 사용.
* **경고/충돌 (Alert):** 눈을 찌르지 않는 톤다운된 **파스텔 레드(#FF6B6B)**. 중복 배정이나 오류 발생 시 텍스트나 블록 테두리에 적용.
* **텍스트 컬러:** 완전한 검은색(#000000) 대신 가독성이 높은 **다크 그레이(#333333)**를 사용하여 대비를 부드럽게 조정.

### 7.2. 타이포그래피 (Typography - 큰 글씨)
모바일과 PC 화면 모두에서 돋보기를 쓰지 않아도 한눈에 들어오도록 폰트 크기를 상향 조정합니다.
* **서체:** 가독성이 뛰어난 고딕 계열(Pretendard, 맑은 고딕 등) 단일 폰트 사용.
* **기본 폰트 크기:** 일반적인 앱(14px)보다 큰 **16px~18px**을 기본 본문 크기로 설정.
* **시간표 블록 폰트:** 모바일 화면에서도 터치하기 쉽도록 시간표 셀(Cell) 안의 교사 이름과 과목명은 **Bold(굵게)** 처리.
* **제목 폰트:** 화면 상단의 메뉴나 시험 프로젝트명은 **22px 이상**으로 키워 현재 위치를 명확히 안내.

### 7.3. 레이아웃 및 여백 (Layout & Spacing - 깔끔함)
정보가 뭉쳐 보이지 않도록 '여백의 미'를 최대한 활용합니다.
* **카드형 디자인 (Card UI):** 교사별 불가 시간 리스트나 개인별 시간표는 각각 테두리가 둥근 하얀색 카드(Card) 위에 올려 배경과 분리합니다.
* **터치 영역 극대화:** 버튼의 높이를 최소 **48px 이상**으로 큼직하게 만들어, 스마트폰에서 조작할 때 오터치가 발생하지 않도록 설계합니다.
* **선택적 정보 표시:** 한 화면에 너무 많은 정보를 뿌리지 않고, 꼭 필요한 정보(교시, 반, 이름)만 크게 보여준 뒤, 상세 정보는 블록을 클릭(또는 터치)했을 때 팝업으로 나타나도록 숨깁니다.
